四、软件主要功能
----------------

1. HTTP(S) 接口可用性监控：对配置的目标 URL 定时发起请求，支持状态码断言、
   响应体关键字断言、超时与连接失败判定，并测量请求延迟；
2. TLS 证书到期监控：通过 TLS 握手拉取服务器真实证书链，计算各证书剩余天数；
   支持对本地 PEM 证书文件做离线检查（无法直连、内网/离线场景）；
3. 简易 APM 采集：接收受监控进程上报的请求延迟/错误采样，计算并展示
   p50 / p95 分位数与错误率，支持慢响应阈值告警；
4. 灵活调度：cron 风格调度网格，每个检查项独立配置周期（30 秒至 5 分钟），
   慢任务不重叠；间隔可整体配置，也可按单条检查覆盖；
5. 多渠道告警：桌面通知（notify-send）、Webhook（POST JSON）、邮件 SMTP
   （自研客户端，支持 AUTH PLAIN 与 STARTTLS），重复告警按周期去重；
6. 双形态界面：终端 TUI（绿/黄/红状态 + 延迟 sparkline + APM 曲线）与 Web
   单页（状态表格 + 三层历史曲线：延迟 / TLS 剩余天数 / APM 分位与错误率，
   每个被监控目标一条独立彩色曲线，含告警阈值虚线）；
7. 时间加权可用率：基于状态快照历史计算 uptime%（warn 计为在线，与 Datadog
   口径一致），展示于 Web、导出 JSON 与 HTML 状态页；
8. 状态导出：将当前健康状态导出为 JSON 或自包含 HTML 状态页，可直接托管于
   静态服务器/CDN；
9. 监控器自健康：引擎周期性记录 uptimeSince / lastCheckAt / 最差状态并写入
   存储，Web 顶栏、TUI 表头、导出页面统一展示「up 时长 / 上次检查 / 状态」；
10. 数据留存：SQLite 存储状态快照、时间序列、事件日志与元数据，后台任务
    按 retentionDays（默认 7 天）自动裁剪过期数据，长时间运行不增长内存
    与磁盘。

五、软件技术特点（创新点）
--------------------------

1. 零第三方依赖的轻量架构：仅使用 Node.js 内置模块（node:sqlite、node:tls、
   node:crypto、node:http 等）实现完整的监控、存储、告警、界面闭环，无需
   安装任何第三方包即可运行，部署成本极低；
2. 自带手写 SMTP 客户端：直接基于 node:net / node:tls 实现 SMTP 协议，支持
   AUTH PLAIN、STARTTLS 升级、完整信封校验，不依赖 nodemailer 等外部库；
3. 进程内 SQLite（WAL 模式）时间序列：状态快照、延迟曲线、APM 分位与事件
   统一落入本地单文件数据库，配合 WAL 与 NORMAL 同步模式兼顾可靠与性能；
4. 「慢即告警」分级语义：HTTP 探测在状态断言通过但延迟超过阈值的场景下将
   状态降级为 warn（黄色），不再把慢响应伪装成健康绿；APM 以 p95 是否越过
   latencyThresholdMs 判定告警，与 Datadog 的慢接口口径一致；
5. 时间加权可用率：用「当前状态持续到下一次快照」的加权算法计算 uptime%，
   对长时间处于 warn 的证书到期目标仍能给出接近满额的可用率，避免误报
   为 0%；
6. 证书探测的健壮链解析：兼容 node 20 以上多种 getPeerCertificate(true)
   返回形态（对象、指纹键对象、数组、raw DER / PEM），并支持对本地 PEM
   多证书链做离线解析与链序校验；
7. 配置 fail-fast 校验：启动即校验配置结构（如 http 写成对象而非数组、
   TLS 条目缺 host 与 pemFile、非法端口/阈值/间隔），出错立即可读并退出；
8. 监控器自健康与全通道一致性：引擎在每次检查路径（调度任务、一次性运行、
   tick）均持久化自身健康信息，Web / TUI / JSON / HTML 导出四种界面展示
   一致的「up 时长 / 上次检查 / monitor 状态」；
9. 单文件自包含 HTML 状态页：export 输出内嵌全部样式，零外部依赖，可直接
   放到静态托管/CDN 分享；
10. 24 小时加速模拟验证资源上限：内置 memory 测试，断言运行时 RSS < 200MB，
   保证长时间后台运行不膨胀。
